**mYcopilot** — the capital Y is a crossroads: three paths from one point. You choose which way to go.

Documentation for this copilot is made with this very copilot.

It is [regenerated](./prepare-for-publishing.sh) from scratch for each version. I believe this is a good approach for many projects — simple or not — because it encourages keeping things understandable.

The dialogue form of documentation shows how this copilot works. Each question is marked with `# Us` (User), each answer with `# As` (Assistant). Each run of the copilot generates a new assistant answer and the log shows what is happening.

Efficiency comes from understanding what is happening and treating the dialogue as a query. Change your previous questions, simplify or rewrite assistant answers, and you'll use fewer tokens and get greater precision. With LLMs, you can trade quality for speed — or find a balance where both improve. The latter is usually the better choice.
