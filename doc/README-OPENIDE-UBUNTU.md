## What is `copilot-v2.main.kts`?

This is a **Kotlin-based AI coding assistant (copilot)** built on the [Koog framework](https://github.com/JetBrains/koog) by JetBrains. It implements a multi-tool AI agent that reads a dialogue from a Markdown file, sends it to an LLM, and iteratively executes tools — such as reading/writing files, searching the internet, analyzing images, running scripts in a Docker sandbox — until the task is resolved. The assistant's response is then appended back to the same Markdown file, making it a file-driven conversational loop. It is designed to be launched via a hotkey in an IDE (IntelliJ external tools or VS Code tasks), turning any `.md` dialogue file into an interactive coding session.

The script is highly configurable at the bottom of the file via a set of tuning functions. The author, based in Russia, pays special attention to **LLM provider accessibility** — using **Kodik Router** (a Russian API proxy whose API is OpenAI-compatible, hence the `OpenRouterLLMClient` adapter is reused) or **Dashscope** (Alibaba Cloud, noted as very cheap). The `searchProviderTuning()` enables web-search plugins for the research sub-agent. The tool set can be toggled per dialogue step by commenting/uncommenting entries in `currentTools()`.

Key architectural features include: a **proposal-based file modification system** (edits go to a `.proposal` file first unless the path is whitelisted for direct modification), **PII/API-key redaction** before sending prompts to the LLM (passports, credit cards, API keys, etc. are masked), **superseded-read cleanup** (old `readFile` results are pruned to save tokens), and a **read-before-modify enforcement rule** that blocks modifications to files the agent hasn't read first. All of this makes it a self-contained, safety-conscious, IDE-integrated AI pair programmer.

## Step 1 — Install JDK 17+

Download and install any JDK 17+ distribution (e.g. [Eclipse Temurin](https://adoptium.net/), JetBrains Runtime, or Oracle JDK).

Verify in `cmd`:
```cmd
java -version
```
You should see `openjdk version "17.x.x"` or higher.

## Step 2 — Install Kotlin 2.3.20

1. Go to [GitHub Releases — Kotlin v2.3.20](https://github.com/JetBrains/kotlin/releases/tag/v2.3.20).
2. Download **`kotlin-compiler-2.3.20.zip`** (≈ 79 MB).
3. Unzip to a permanent location, e.g. `C:\kotlinc`.
4. Add `C:\kotlinc\bin` to your system **PATH** environment variable.
5. Verify:
   ```cmd
   kotlin -version
   ```
   Expected output: `Kotlin 2.3.20 ...`

> **Why the standalone compiler?** The script uses `@file:DependsOn(...)` annotations that resolve Maven artifacts at runtime. This requires the Kotlin scripting infrastructure bundled with the standalone compiler (not just the IDE plugin).

## Step 7 — Run from Command Line

The critical piece: you **must** pass the serialization compiler plugin via `-Xplugin` (Doc hint, lines 1–3). Without it, structured output (JSON serialization) won't work.

```cmd
cd D:\my-some-great-project\assistant

kotlin -Xplugin "C:\kotlinc\lib\kotlinx-serialization-compiler-plugin.jar" copilot-v2.main.kts dialogue.md
```

> **Note:** The first run may fail silently due to dependency caching. If so, run the same command a second time.

## Step 8 — Set Up IntelliJ IDEA External Tool + Hotkey

This is the recommended workflow (Doc hint, lines 4–5):

### 8a. Create the External Tool

1. Open IntelliJ IDEA → **File | Settings** (`Ctrl+Alt+S`)
2. Navigate to **Tools | External Tools**
3. Click **`+`** (Add) and fill in:

   | Field | Value |
   |---|---|
   | **Name** | `Run Copilot` |
   | **Group** | `Copilot` |
   | **Program** | `C:\kotlinc\bin\kotlin.bat` |
   | **Arguments** | `-Xplugin "C:\kotlinc\lib\kotlinx-serialization-compiler-plugin.jar" "D:\my-some-great-project\assistant\copilot-v2.main.kts" "$FilePath$"` |
   | **Working directory** | `D:\my-some-great-project\assistant` |

4. Click **OK**.

### 8b. Assign a Hotkey

1. In Settings → **Keymap**
2. Search for `Run Copilot` (or expand **Main Menu | Tools | External Tools**)
3. Right-click → **Add Keyboard Shortcut**
4. Press your preferred combination, e.g. **`Ctrl+Shift+P`**
5. Click **OK**.

### 8c. Usage

1. Open any `.md` dialogue file in the editor (e.g. `dialogue.md`)
2. Write your question after `# Us`
3. Press **`Ctrl+Shift+P`**
4. Wait — the copilot will process the dialogue, call tools, and append its response after `# As`

## Troubleshooting

| Problem | Solution |
|---|---|
| `structured output won't work` / JSON errors | You forgot `-Xplugin` — the serialization compiler plugin is mandatory (Doc hint, line 3) |
| First run fails silently | Run the same command again — dependency resolution caches on first run |
| `ERROR: Unsupported client` | Check that `providerTuning()` uses either `OpenRouterLLMClient::class` or `DashscopeLLMClient::class` (line 141) |
| `apiKey` is null | Make sure `.env` is in the **working directory** (the `assistant` folder) and contains the correct key variable name |
| Docker tools fail | `runScript` is disabled by default (line 1595). Uncomment it only if you have Docker Desktop installed and a `Dockerfile` in the `assistant` folder |
| Paths not found | The copilot resolves relative paths from `basePath()` = parent of the `assistant` folder (line 1584). Always use absolute paths in dialogues for clarity |
